# Compatibility

No release workflow is currently claimed as supported. The machine-readable source of truth is `compatibility/features.yaml`.

Status values are limited to `untested`, `pass`, `pass_with_workaround`, `partial`, `fail`, `crash`, and `unsupported`. A Tier A entry may change to `pass` only after its named test is run on both the candidate Mac runtime and the Windows reference where rendering is involved.

The bridge protocol framing and raw native capture are implemented, but the public YMM4 API's frame pixel layout and audio sample layout have not been established. Native export therefore remains `partial` and must not reinterpret bytes as BGRA, RGBA, or any other guessed format.

The 2026-08-24 unpatched baseline established the Direct2D/DXGI failures. On 2026-08-25 through 2026-08-27 the isolated source-patched DXMT/Wine development runtime advanced through project open, preview playback, PNG/JPEG and WAV/MP3 loading, animated-GIF decoding, Japanese text rendering, H.264/AAC video import and matched-setting round-trip export, software export, and repeated compute dispatch/readback. One DXMT pure-virtual stop was observed but did not recur in the controlled GIF retry and is not attributed to a format. A reproducibly staged clean candidate assembled from Wine Stable 11.0 resources and only source-built Wine/DXMT replacements passes the eight-fixture suite, confines its managed DXMT surface to YMM4's preview pane, visibly renders the WPF UI under the required software profile, and completes YMM4's 3-second Japanese H.264/AAC export; it includes no CrossOver files. Its `YukkuriMovieMaker.Win32Service.exe` child reproducibly emits a Mono native-crash banner and YMM4 logs WMI initialization failures, while the main process remains functional; impact is not yet assigned. Japanese Romaji IME confirms text in Wine Notepad and a runtime-matched WPF control but not directly in YMM4's field. A version-scoped native macOS input overlay passes the IME001 conversion/editing/shortcut matrix and transfers explicitly committed text through documented Unicode input events without pressing Add, so IME001 is `pass_with_workaround`. The overlay text can be added and saved, but current-candidate reopen now stops for both that new project and a previously passing control, so PROJECT001 is `fail`. This is still a development result, not a shipping-runtime claim: project reopen, repeated GIF stability, video thumbnail and split editing, remaining media formats, audible output, reference rendering, licensing, packaging, and signing remain open.
