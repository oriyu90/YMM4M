Host: Apple M3 Ultra, macOS 26.4, Rosetta 2 installed.

Subject: user-supplied YukkuriMovieMaker v4.55.1.1 Lite, AMD64, self-contained .NET 10.0.10. Archive SHA-256: `125860147cc33b831fc1a6d6ea996958001c2ead3b0d37f7d900251d5617db9b`.

The main WPF window and standard dialogs were enumerated by public Win32 APIs. The error details came from YMM4's own application log. No proprietary implementation was decompiled.

Decision: no production runtime or edit renderer is selected. The Direct2D/DXGI gap needs a minimal reproducer and a runtime fix before the minimal editing workflow can proceed.

## Standalone reproducers

`d2d-device6-reproducer.cpp` confirms that CrossOver WineD3D and D3DMetal return `E_NOTIMPL`, while DXMT completes `ID2D1Device6.CreateDeviceContext` successfully.

`dxgi-surface2-reproducer.cpp` then reproduces the exact DXMT failure independently of YMM4: a two-buffer `DXGI_SWAP_EFFECT_FLIP_SEQUENTIAL` chain is created, but `GetBuffer(0, IID_IDXGISurface2)` returns `E_NOINTERFACE` and logs GUID `aba496dd-b617-4cb8-a866-bc44d7eb1fa2`.

DXMT main at `e55ad281c60be97f8815b5848e57cfd9f967d759` still lacks this surface identity. A candidate patch is recorded under `patches/`, but is not adopted because the full Xcode/LLVM/Wine cross-build toolchain is not available for compilation and regression testing.
