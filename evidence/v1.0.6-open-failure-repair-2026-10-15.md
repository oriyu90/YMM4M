# v1.0.6 open-failure repair — evidence (2026-10-15)

Machine: Apple M1 Max / macOS 27.0 (Build 26A428) / CLT + Xcode.app 26.4.1
Repo: `oriyu90/YMM4M` branch `claude/ymm4m-v1.0.6-open-fix` (based on `main` `bbee38b` v1.0.5)

## Reported problem

Users reported YMM4M "does not work (cannot even open)".
Production runtime/prefix/YMM4 on this Mac are intact
(`Runtimes/current` + `Prefixes/current` + `YMM4/current` → 4.55.1.1-Standard,
Lite in `previous`; CLI `--help` exits 0 via `arch -x86_64 wine`).
Upstream YMM4 latest is still v4.56.1.0 (2026-09-04), so the catalog
(4.55.1.1 known + 4.56 family) is not the trigger.

## Root causes found (code audit + live repro)

1. Empty folders counted as configured (`YMM4MApp.configuredRequiredCount`
   `!$0.isEmpty`). Fresh users picking empty stores saw 4/4 ready, then
   failed late in `probe()`/`validateCleanRuntime` with manifest messages.
   This Mac's own defaults point at empty
   `/Users/yuki/Places_M1/App/runtime for ymm4` (+ `...42`) with spaces —
   exactly the trap.
2. UI tasks mutated `@State`/`@AppStorage` off-main and called
   `@MainActor NSAlert.runModal()` from `Task {}` without isolation —
   hang/crash on the launch click (Swift 6.2). Plus `projectURL!`
   force-unwraps and a manifest `files[]!` force-unwrap.
3. Rosetta no-`arch` fallback trusted the stale `oahd` marker (macOS 27
   leaves the stub). Bare hosts would build for hours then never launch.
4. Custom stores with colons/tabs/newlines would silently split
   colon-joined `WINEDLLPATH` or break shell quoting. Spaces stay allowed
   (the standard `Application Support` path itself contains a space and
   works; the compile happens in the whitespace-free cache). The UI and
   bootstrap now reject only what actually breaks the launch.
5. Renamed maintenance ZIPs failed only after the runtime build
   (`verify()` filename gate runs post-build). Known-hash renamed ZIPs work,
   maintenance ones do not — undiscoverable until hours in.
6. Prefix-only path skipped `hb-subset` preflight; interrupted empty
   `NotoSansCJKjp-Regular.otf` counted as installed (`-f` vs `-s`).
7. Docs stale: `MAC_SETUP.md` v1.0.3 + old DMG name + "toolchain auto-fetch
   unimplemented" (contradicts auto-fetch), `RELEASE_DMG_NOTICE.txt` 1.0.0,
   `build-release-dmg.sh` defaults 1.0.0. Gatekeeper steps omitted
   copy-to-/Applications, Right-click Open, quarantine handling.

## Fixes (all fail-closed, JA/EN)

- `YMM4MApp`: launch/check require existing manifest/wine, `user.reg`,
  readable exe, existing media dir; custom `.../current` pairs verify
  binding (schema + profile). All UI tasks `Task { @MainActor in }`;
  `projectURL!` removed; host notice also on launch.
- `resolvedSetupPaths`: colon/tab/newline rejected with new
  bilingual `errorCustomPathWhitespace` (Loc ja/en 126/126, `versionBadge`
  v1.0.6). Spaces stay allowed.
- `runCompleteSetup`: `preflightArchiveBeforeBuild()` hashes first (known
  → proceed regardless of filename; unknown + non-official name → stop
  with `archiveFileNameChanged` before any download/build) + media-dir check.
- `RosettaWineBackend.rosettaAvailable`: no-`arch` → false (was marker).
  Manifest loop force-unwrap removed.
- `bootstrap-wine-dxmt-runtime.sh`: runtime/prefix colon gate, per-volume 10 GiB + 2 GiB checks, no-arch
  fail-closed, plan text updated. (Whitespace gate stays source/build-only;
  a colon-separator self-match bug was caught by Python tests and fixed.)
- `setup-prefix-from-runtime.sh`: per-volume 2 GiB checks + `hb-subset`
  early gate.
- `configure-japanese-fonts.sh`: `-s` reuse check (empty file regenerated).
- Docs: `MAC_SETUP.md` v1.0.6, DMG name, Gatekeeper (copy, Right-click,
  Open Anyway, SHA-256, never disable), toolchain correction, space/
  whitespace/renamed notes. Notice + script defaults to v1.0.6.
