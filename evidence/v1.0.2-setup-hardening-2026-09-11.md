# v1.0.2 setup hardening — 2026-09-11

Host: Apple M1 Max, macOS 26.5 (25F71), arm64. Command Line Tools only.
No local Wine runtime, no YMM4 ZIP, no Homebrew build tools on this machine:
the full multi-hour bootstrap could not be run end-to-end here, so every
change below is either host-side testable or fail-closed by construction, and
no runtime/patch/fixture/catalog behavior was touched.

Task: verify that setup on any macOS 26+ Mac is just "choose folders + choose
the YMM4 ZIP", and fix gaps.

## Findings and fixes

1. **Brewfile missing from the DMG.** The setup remedy and `MAC_SETUP.md`
   say `brew bundle --file=Brewfile`, but `tools/build-app.sh` never bundled
   it, so a DMG-only install had no such file. Fix: bundle
   `Contents/Resources/RuntimeBootstrap/Brewfile` (0644, MIT, no license
   impact); the bootstrap resolves the sibling copy, else the repo copy, and
   prints the exact command. Verified: `build-app.sh` output contains it;
   synthetic bundled layout prints
   `brew bundle --file="/tmp/fakebundle/Brewfile"`.
2. **Preflight missed `flex`.** Wine's configure needs flex + bison; only
   bison was checked, so a Mac without flex would fail after long downloads.
   Fix: `flex` added to the aggregated preflight (present via CLT on normal
   Macs, so no behavior change there). Verified on this machine: preflight
   still aggregates (`meson ninja x86_64-w64-mingw32-gcc bison(>=3)`) and
   exits 2 before any download.
3. **No Homebrew-missing remedy.** Without `brew`, the old message printed a
   `brew bundle` command that cannot run. Fix: Homebrew-first remedy
   (https://brew.sh) when `brew` is absent.
4. **No free-space gate.** Only UI text mentioned ~10 GB; a full disk failed
   hours into the compile. Fix: `df -k` gates before any download (~10 GiB
   full bootstrap incl. LLVM extraction; ~2 GiB prefix-only path).
5. **Silent hours look like a hang.** Downloads, Wine/DXMT compiles, wineboot,
   and the fixture gate printed nothing for minutes-to-hours; a user may
   force-quit a healthy build. Fix: background heartbeat every 120 s with the
   current phase tag; the host now also forwards `[gate]`. Heartbeat starts
   after `--plan`/`--check-urls` early exits, so those outputs are unchanged;
   an EXIT trap always stops it.
6. **Whitespace in $HOME breaks the build late.** `Application Support` is
   fine, but the Wine compile cache defaults under `$HOME/Library/Caches`
   and the script hard-fails on whitespace there. A home directory with a
   space/tab is possible on any Mac. Fix: the host computes
   `compileCacheRoot` (usual cache when whitespace-free, else per-user
   `$TMPDIR/YMM4M-Build`) and exports `YMM4M_COMPILE_CACHE_ROOT`, unless the
   user already set it. The script's own whitespace refusal stays as a safety
   net. Pure, unit-tested decision.

## Compatibility / safety review of the diff

- Bootstrap protocol unchanged: same pinned sources/hashes/mirrors,
  same staging/gate/fixture flow, same fail-closed refusals. Added checks run
  before downloads and can only stop earlier with clearer messages.
- Heartbeat writes one line per 120 s to stdout (→ setup log + status); no
  build-command semantics changed; phase tags reuse the existing forwarded set
  plus honestly-labeled `[gate]`.
- `compileCacheRoot` is pure; `install()` only adds an env var the script
  already honored. Explicit `YMM4M_COMPILE_CACHE_ROOT` still wins.
- `build-app.sh` adds one MIT text file; DMG audit impact is limited to a
  LEGAL-AUDIT addendum line at release time (no new content kinds).
- Dead UI helper `runAutomaticSetup()` left untouched (out of scope; the
  shipped flow is `runCompleteSetup`).

## Remaining open (by design, disclosed)

- Full clean-machine end-to-end bootstrap timing (multi-hour) unmeasured on
  fresh hardware; resume-after-interruption path is code-reviewed, not
  re-run here.
- Prebuilt-runtime distribution still requires the full audit runbook gates.
