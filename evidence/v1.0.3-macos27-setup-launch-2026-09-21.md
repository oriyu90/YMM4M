# v1.0.3: macOS 27 setup→launch end-to-end evidence (2026-09-21)

実機: Apple M1 Max / macOS 27.0 (26A428) / CLTのみ + Xcode.app 26.4.1（Metal
Toolchain導入済み）/ Rosetta 2（本セッションで再導入）。
対象: `claude/ymm4m-v1.0.3-macos27`（v1.0.3候補）。

## 報告との対応

「セットアップを完了しても開くことができない」という報告について、
macOS 27.0実機で最初から最後まで再現・特定・修正・検証した。

### 原因1: Rosettaの見かけ判定（起動失敗の直接原因）

- macOS 26.5→27.0へのアップグレードで、インストール済みRosetta runtime
  （`/Library/Apple/usr/libexec/oah/` 配下・receiptなし）が削除されていた。
- 一方 `/usr/libexec/rosetta/oahd` は残るため、YMM4Mの従来判定
  （`oahdExists || archProbe()`）は「利用可能」と誤判定し、
  `arch -x86_64 /usr/bin/true` は `Bad CPU type in executable` で失敗した。
- つまり「セットアップ済みに見えるが起動できない」状態になる。
- 修正: 機能プローブ（実際のx86_64実行）を真とし、マーカーは
  `/usr/bin/arch` が無いbare-bones hostのfallbackに格下げ。
  `RuntimeBootstrapper.install` の先頭でも同じ機能ゲートを通し、
  download/build前に `softwareupdate --install-rosetta --agree-to-license`
  を含む日英メッセージで停止するようにした。
- 本機では `softwareupdate --install-rosetta --agree-to-license` で
  Rosetta 2を再導入し、プローブ成功を確認してから検証を続けた。

### 原因2: DXMT buildにMetal compilerが必要（新規setupの失敗原因）

- DXMTは `dxmt_command.metal` を `xcrun -sdk macosx metal` でbuildするが、
  このcompilerはフルXcodeにしか入っていない（CLTのみのMacでは失敗する）。
- 修正: preflightで1回だけprobeし、現在developer dirで動かなければ
  `/Applications/Xcode.app` をDXMTのbuild工程だけに使う
  （工程内`DEVELOPER_DIR`、マシン全体の`xcode-select`は不変）。
  無い場合はdownload前に `xcodebuild -downloadComponent MetalToolchain`
  の導入手順を表示して停止する。

### 原因3: DXMT Unix libのlibc++参照（gate失敗の直接原因）

- DXMTの `winemetal.so` はLLVM 15 toolchain付属のlibc++を
  `@rpath/libc++.1.dylib` としてlinkする（toolchainの`-L`がsystemより優先）。
  toolchainはstageしないため、完成runtime内で解決できず
  `get_builtin_unix_funcs failed to load ... winemetal.so:
  Library not loaded: @rpath/libc++.1.dylib` となり、
  fixture gateが `loader_init "winemetal.dll" failed ... c0000142` で失敗した。
  macOS 27では `/usr/lib/libc++.1.dylib` のsymlinkも無いため顕在化した。
- 修正: bootstrapのDXMT build直後に `install_name_tool -change` で
  system runtime（`/usr/lib/libc++.1.dylib`、shared cache経由で解決）へ
  向け直す。code変更ではなくloader pathのみ。残留があればfail-closed。
  診断時は一時的にtoolchainのdylibを並べて原因を確定した
  （compute fixtureが `completed 2/2` / rc=0になることを確認）。
- schema-2のfixture gateはこの修正済みbinary群に対して通過したため、
  信頼の根拠（固定入力＋patch＋gate通過）は保たれている。

## 検証結果（本機・macOS 27.0）

- `--plan`: Rosetta working / Metal compiler via Xcode.app と表示。
- `--check-urls`: 全effective pinned inputが到達可能（exit 0）。
- フルbootstrap: Wine 11.0 build → DXMT build（metal＋libc++修正）→
  stage → prefix作成 → 8-fixture＋compute100 gate通過 →
  `finalized runtime fixture gate`。
- `RuntimeBootstrapper.install`＋`validateActivePair`＋
  公式4.55.1.1 Lite ZIP（SHA-256照合済み）の新規導入＋M:割当まで
  本番コードパスで完了（`SETUP-OK`）。
- 起動: probe成功 → `LAUNCH-OK`（pid存続）。YMM4 v4.55.1.1 Liteの
  splash → 初回update確認 → About → メインウィンドウ
  （`YukkuriMovieMaker v4.55.1.1 Lite`、menu/preview/timeline/台詞欄描画）
  まで可視確認。Win32ServiceのMono bannerは既知のもの（HANDOFF §7）。
- YMM4MホストGUI: 日英ともmacOS 27で起動・描画（v1.0.3バッジ）。
  - `evidence/ymm4m-setup-ja-macos27-2026-09-21.png`
  - `evidence/ymm4m-setup-en-macos27-2026-09-21.png`
- YMM4本体:
  - `evidence/ymm4-splash-macos27-2026-09-21.png`
  - `evidence/ymm4-update-check-2026-09-21.png`
  - `evidence/ymm4-lite-main-window-macos27-2026-09-21.png`
- 検証後の後片付け: `current` はStandardへrollback（Liteはpreviousとして保持）、
  診断用に置いたdylibはstage領域から除去し、次回bootstrapで再stage済み。
  YMM4プロセスはオーナーの操作に委ね、killしていない。
