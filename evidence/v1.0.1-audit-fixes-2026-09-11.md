## GPU / accelerator audit (can YMM4 draw with the GPU?)

- YMM4/WPF UI: **software by design**. The required
  `Avalon.Graphics\DisableHWAcceleration=1` prefix profile is enforced by
  `RosettaWineBackend.hasRequiredWPFSoftwareProfile`; no code path enables a
  hardware WPF path. Portable across all Apple Silicon; no GPU use to break.
- Editing/preview surface: **partial Metal** through the source-patched DXMT
  (`winemetal` override: `d3d10core,d3d11,dxgi,winemetal,d2d1,dwrite=b`). This
  machine reports Metal 4 on M1 Max; the DXMT/Metal bridge uses only the
  Wine-managed client surface with no per-model tuning, so the same binaries
  apply to M1–M4. Full-session Metal-work equivalence to Windows is still
  unmeasured (open runbook Phase B item, unchanged).
- FFmpeg decode/encode inside YMM4: **software**. YMM4's bundled FFmpeg runs
  under Wine; decoded frames upload through the DXMT/Metal path for preview
  only. The host `ffmpeg` (with VideoToolbox) is a dev-probing tool, not
  invoked by the app; the native ARM64 encoder process exists for a future
  VideoToolbox wiring that is not claimed.
- NVENC: `unsupported` (Tier D) — correct, Apple Silicon has no NVIDIA GPU.
- D3D12 profile: disabled. WebView2: untested. Neither is claimed.
- `Win32Service.exe` WMI/GPU-enumeration failure remains log noise from a
  non-essential companion process; no launch-path change (B1 decision kept).
- Conclusion: **no GPU code changes in v1.0.1** — the documented split
  (software UI / Metal preview / software encode) is correct and portable, and
  changing it without a Windows reference plus hardware matrix would violate
  the evidence rule.

## Compatibility / safety review of the v1.0.1 diff

- Error cases, `RuntimeBackend` protocol, manifest schemas, pinned hashes,
  fixture gate, atomic-channel and recovery semantics: unchanged.
- `CoreMessages`/`message(for:)` are pure string renders (no I/O, no
  allocation beyond the string); `errorDescription` reads the process locale
  dynamically, so no cached-locale staleness.
- `rosettaAvailable` short-circuits: the `arch` subprocess runs only when the
  marker is absent (zero cost on normal Macs); `archExecutableURL` is checked
  before every Wine spawn with a localized fail-closed error.
- `HostCompatibility` is advisory-only; it cannot refuse a launch.
- `--check-urls` now probes the same URL set `download()` consumes; doc-only
  mirrors cannot fail the gate or be downloaded.
- `build-release-dmg.sh` defaults reproduce the exact 1.0.0 invocation.
