# YMM4M v0.1.0 development candidate

This is an unpublished development candidate, not a release-ready distribution.

## Artifact

- `YMM4M-0.1.0-build12-development-adhoc.dmg`
- SHA-256: `2891f917ded6710909ced501c4c0f88f6f8a5bc5ecf1f3952a980189a18ded4c`

The DMG contains no YukkuriMovieMaker4, Wine/DXMT binaries, CrossOver,
Microsoft runtimes/fonts, plugins, voice engines, or test media.

## Changes

### Build 12

- The automatic installer now populates the folders chosen in
  "個別セットアップ・開発者向け詳細設定". With both the 互換ランタイム and
  専用prefix folders set, "互換環境を一括インストール" roots the standard
  versioned `versions/<profile>` + atomic `current` layout at those folders and
  completes the whole setup there, instead of always installing under
  `~/Library/Application Support/YMM4M`.
- Same-folder, home-directory, and filesystem-root selections stop before setup
  starts with a stated reason. `YMM4M_RUNTIME` / `YMM4M_WINE` / `YMM4M_PREFIX`
  environment overrides still take precedence.

### Build 11

- The one-pass installer no longer needs a hand-provisioned x86_64 LLVM 15
  toolchain. When `YMM4M_LLVM15_ROOT` is absent, the pinned upstream LLVM 15.0.7
  x86_64 release is downloaded and SHA-256 verified like every other bootstrap
  input, then used only as a DXMT build tool. It is never staged into or shipped
  with the runtime.
- The bootstrap preflights Rosetta 2 before downloading or building, instead of
  failing at the staging step after a long compile. The message points at
  `softwareupdate --install-rosetta`.
- Missing Homebrew build tools and unverified MinGW GCC versions print the exact
  install / `brew pin` commands. Other GCC majors stay refused because the app
  validates staged PE hashes against two audited variants.
- `docs/MAC_SETUP.md` lists the concrete `softwareupdate` / `brew install`
  prerequisites and the corrected (~10 GB) free-space requirement.

### Build 10

- Replaced the separate normal-user runtime, ZIP, and media steps with one
  complete installer. After consent, the only selected inputs are the official
  Standard/Lite YMM4 ZIP and the media/project folder.
- Added recoverable retry from incomplete runtime, prefix, current-channel, and
  managed YMM4 destinations. Invalid managed entries move to `Recovery`; valid
  active/older versions and external paths are not overwritten.
- Save setup settings only after runtime, prefix, managed YMM4 copy, M: mapping,
  and final validation all pass. A repeated setup reuses the verified result.
- Fixed fresh-prefix setup waiting forever on an orphaned interactive Wine
  debugger, while retaining Wine exit, registry, WPF, font, marker, manifest,
  and binding validation plus prefix-scoped process cleanup.
- Fixed repeated YMM4 installation misclassifying a valid relative `current`
  symlink as external.
- Fixed automatic runtime setup end to end: live phase progress, persistent
  diagnostic log, bounded network timeouts, whitespace-safe compile caches,
  and correct pinned DXMT submodule placement.
- Added a fully verified GCC 16.2 runtime hash variant alongside the prior GCC
  15.2 variant. Unknown compiler versions and mixed hash sets fail closed.
- Clarified that the runtime folder remains empty until final validation and
  atomic activation; the setup counter no longer implies that paths are valid.
- Advanced the managed runtime/prefix profile to patchset5 and verified a full
  clean download/build/stage/prefix/current-channel flow.
- Hardened activation and rollback so reused candidates and previous versions
  are fully revalidated before an atomic channel change; failed validation leaves
  the active version unchanged.
- Added provisional future stable 4.55.1.x Standard/Lite intake. An unknown ZIP
  must match the fixed official GitHub release asset name, size, and SHA-256,
  pass the safe ZIP and AMD64 Windows GUI PE checks, and preserve the recorded
  self-contained .NET/WPF runtime boundary.
- Kept provisional `maintenanceCandidate` separate from `knownCompatible` and
  added one-click rollback to the prior managed YMM4 version.
- Added Standard/Lite-separated shared YMM4 user-data roots. Settings written
  through one managed version remain visible after update and rollback; legacy
  Lite data is copied without deleting the source.
- Added hash-pinned YMM4 4.55.1.1 standard-edition ZIP installation, CLI
  help, first-run, main-window startup, and same-prefix restart verification.
- Added restart persistence contracts for all five YMM4M setup values and safe,
  idempotent legacy managed-path migration to existing `current` channels.
- Clarified that users should retain the official ZIP in a location that is not
  automatically deleted; YMM4M does not move, modify, or delete the source ZIP.
- Added `ZIPを選んで準備`: validates a user-supplied official YMM4 ZIP and
  extracted executable, installs it by version, and atomically activates it.
- Added `YMM4をMacで開く` to launch the prepared YMM4 in a Wine/macOS window.
- Added a machine-readable YMM4 release catalog bound to a tested runtime
  profile.
- Made runtime and prefix installation versioned, retained older versions, and
  added atomic current-channel switching and runtime/prefix binding checks.
- Added legacy-layout migration and safe recovery from a partial channel switch.
- Added update-resilience architecture, maintenance, setup, and evidence docs.

  payload scan, app GUI launch and clean quit: pass

## Important limitations

- Release trains outside 4.55.1.x, pre-releases, changed runtime boundaries,
  and assets that cannot be verified against the official API are refused.
- Maintenance candidates are not behaviorally verified releases. Manual
  rollback is available, but automatic crash-loop rollback is not implemented.
- Direct Japanese IME remains a version-scoped native-overlay workaround.
- Detailed standard-edition editing/media/export coverage remains incomplete;
  those Tier A results are not inferred from Lite.
- Remaining Tier A, Win32Service, clean-machine, extended recovery and final
  license gates are incomplete.
- Developer ID is unavailable, so the artifact is ad-hoc and non-notarized.

Do not publish this draft as a normal end-user release. The deferred final
release-license audit remains unopened because the final gates are incomplete.
